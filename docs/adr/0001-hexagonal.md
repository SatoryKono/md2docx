# ADR 0001: Гексагональная архитектура

## Статус

Принято (2026-07-26)

## Контекст

Монолит `gost_styles_python_docx.py` (~1400 строк) смешивал CLI, парсинг Markdown,
правила ГОСТ/A.docx и запись python-docx. Расширение (новые элементы MD, тесты,
смена бэкенда) было рискованным.

## Решение

Гексагональная (ports & adapters) архитектура:

- **domain** — чистые правила и модель  
- **application** — use cases через Protocol-порты  
- **adapters** — CLI, MD parser, DOCX writer, JSON  

Пакет: `src/md2docx`, тесты: `test/`, документация: `docs/`.

## Последствия

**Плюсы:** тестируемость domain/parser без Word; замена writer; явные границы.  
**Минусы:** больше файлов; нужен composition root; миграция поведения.  

## Альтернативы

- Оставить монолит — отклонено.  
- Clean Architecture с избыточными слоями — избыточно для CLI-утилиты.
